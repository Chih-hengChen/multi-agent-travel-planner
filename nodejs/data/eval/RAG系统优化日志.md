## 待实验方案

### 1. Chunk 参数调优

| 实验 | 参数 | 预期影响 | 优先级 |
|------|------|---------|-------|
| A | maxChars: 500→800, overlap: 80→120 | 上下文更完整 | 中 |
| B | maxChars: 500→300, overlap: 80→40 | 精确度↑，但可能丢失上下文 | 低 |
| C | overlap: 80→160 | 关键片段不丢失 | 中 |

验证：改参数 → `npx tsx src/rag/ingest.ts` 重新入库 → 跑 eval 对比。

### 2. BM25 算法替换

现状：简单词频计分 `score = 命中token数 / totalTokens`

方案：实现 BM25Okapi 算法，考虑文档长度和逆文档频率

预期 MRR +5~10%

优先级：**高**（纯算法改动，不依赖外部服务）

### 3. 修复 Embedding API

现状：`LLM_BASE_URL` 是对话 API，不支持 `/v1/embeddings`

方案 3a：加 `RAG_EMBEDDING_URL` 独立配置
- OpenAI: `text-embedding-3-small`
- 智谱: `embedding-2`

方案 3b：本地模型 `sentence-transformers/all-MiniLM-L6-v2`

优先级：中

### 4. 中文分词改进

现状：单字+双字切分，噪声大
方案：引入 jieba 分词
预期 MRR +3~5%
优先级：低

### 5. 混合搜索

方案：BM25 + 向量余弦相似度 加权融合
前置依赖：先完成实验 2 + 3
优先级：低

### 6. 语料扩充

现状：成都、杭州、重庆内容严重缺失

| 缺失城市 | 影响查询 |
|---------|---------|
| 成都 | 火锅推荐、大熊猫基地、都江堰 |
| 杭州 | 西湖、杭州攻略 |
| 重庆 | 火锅、洪崖洞 |

方案：补充 PDF 或接入百科数据
优先级：**高**

## 实验流程

1. 改代码/参数
2. 重新入库（如涉及 chunk/embedding 变化）
3. 运行评估：`RAG_CHROMA_URL="" node --import tsx/esm src/rag/eval.ts`
4. 记录 baseline.jsonl + 更新本日志
5. 对比指标决定是否上线
